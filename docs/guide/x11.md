# Graphical apps (X11)

With X11 forwarding, a graphical program started in an SSH session (`wireshark`,
`xclock`, `virt-manager`, a vendor's Java console) opens its windows on your computer.
Nothing needs to be installed on the server beyond what `ssh -X` already needs.

## How it works on each platform

| Platform | Local X server | Default |
| --- | --- | --- |
| **Windows** | Built into Muxus (VcXsrv), started the first time a remote program opens a window | **On** for every host |
| **macOS** | [XQuartz](https://www.xquartz.org), which you install once | Off; enable per host |
| **Linux** | Your desktop session's `$DISPLAY` (X11 or XWayland) | Off; enable per host |

The defaults differ because of what a remote program can reach. On Windows it only
reaches the X server Muxus runs for forwarded windows, like MobaXterm's. On macOS and
Linux it shares a display with your other X11 applications and can watch them, so
forwarding is opt-in there, as it is with OpenSSH.

!!! note "First use on Windows"
    The first time the built-in X server starts, Windows may ask whether *VcXsrv* may
    communicate on your networks. Muxus only connects to it over loopback, so it works
    either way; you can safely choose **Cancel**.

!!! note "XQuartz on macOS"
    After installing XQuartz, log out and back in once so that `DISPLAY` is set for
    apps started from the Dock, then reconnect.

## Turning it on or off per host

Open the host editor's **Forwarding** section and choose **X11 forwarding**:

- **Use SSH configuration** (or **Automatic** for hosts stored in Muxus) follows
  `ForwardX11` from matching `Host` blocks, and the platform default above otherwise.
- **Forward X11** writes `ForwardX11 yes`.
- **Do not forward X11** writes `ForwardX11 no`.

Hosts in **console compatibility** mode only request X11 when set to **Forward X11**,
because some network appliances drop the connection on unexpected session requests.

## What the server needs

The SSH server must allow X11 forwarding and have `xauth`:

```text
# /etc/ssh/sshd_config
X11Forwarding yes
```

On Debian and Ubuntu, `xauth` is in the `xauth` package; on RHEL-family systems it is
`xorg-x11-xauth`. When the server refuses, the session still opens without X11. If the
host is set to **Forward X11**, the terminal says why.

## Security

- The server never receives your real X credentials. Muxus sends it a random cookie and
  swaps it for the real one only for connections that present it, like `ssh -X` does.
- The built-in Windows server accepts only a cookie generated each time it starts.
- Forwarding to a macOS or Linux display is *trusted* forwarding (like `ssh -Y`): a
  program on the server can interact with your other X11 windows. Enable it only for
  hosts you trust.
