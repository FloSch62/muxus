# Release 0.14

:material-calendar: 3 November 2026 · [Full changelog](https://github.com/FloSch62/muxus/compare/v0.13.0...v0.14.0)

Release 0.14 shows what runs on your hosts. Docker and Podman containers, Containerlab labs,
Kubernetes pods, Proxmox guests and libvirt VMs appear beside the host they run on and open
in a tab of their own. Tabs mark programs that are working, waiting for you, done or failed,
the taskbar and the Dock open recent hosts and workspaces, and Muxus can be installed with
Nix.

## Containers and VMs on your hosts

While a session to a host is connected, Muxus asks the host's own tools (`docker`, `podman`,
`kubectl`, `pvesh`, `virsh`) what runs there, over the SSH connection that is already open.
Nothing is installed on the host and no port is exposed. This computer is read when the
window opens.

- **Beside the host.** Its sidebar row ends in small counts with each tool's logo: running
  containers, labs, Kubernetes contexts and running VMs. A host that runs none of them looks
  as before. Clicking a count opens the panel on that host.
- **In the panel.** The :material-cube-outline: control in the top bar lists this computer
  and every connected host, with a filter and a **Stopped** toggle. Each line has its own
  actions, and hovering it shows details such as a container's image, ports and ID.
- **In the quick launcher.** ++ctrl+k++ finds containers, lab nodes, VMs and contexts by
  name.

What opens depends on what it is:

- **Containers** open a shell with bash, ash or sh, show their logs, start, stop, restart,
  pause or are removed. A published port opens in the browser, through an SSH forward from
  a remote host.
- **Containerlab** network OS nodes open with SSH as `admin` through the lab host, and Linux
  nodes with a shell in their container. :material-hub-outline: draws the lab's topology.
- **Kubernetes** pods are grouped by workload per context and namespace, with a shell, logs
  and the previous run's logs. With [Kubus](https://kubus-app.dev/) installed, **Open in
  Kubus** shows a pod there.
- **Proxmox** guests open with `pct enter`, `qm terminal` or SSH, and the host offers its web
  interface.
- **libvirt** VMs open their serial console, their VNC display or SSH through the
  hypervisor, so a VM on a private bridge is reachable too.

**Add to hosts** keeps a container, a lab node or a VM in the sidebar, so it opens again like
any host; on this computer a container becomes a local terminal profile.

Connected hosts are read again every 30 seconds, set by **Refresh containers, clusters and
VMs** under **Settings → Behavior**, and a host's data is dropped when its last session
closes. **Find containers, clusters and VMs** switches discovery off, and each host's editor
can override it under **Advanced**. Hosts that never run a command, such as routers, are
never asked.

See [containers & VMs](../guide/environments.md).

## Program status on tabs

Programs that report their state with OSC 7501, the Program Status Protocol, now mark their
tab: a blue ring while they work, filling up when they report progress, an amber question
mark when they wait for a permission, an answer or a sign-in, and a green check or red cross
when they finish or fail. Coding agents and some build and package tools already do this.
It works in local shells as well as SSH, Telnet and serial sessions, since the report travels
in the terminal output.

Hovering the mark shows what the program reported, and the **Show all tabs** menu shows the
same mark. Working and waiting end at the next shell prompt or when the session ends; done
and failed stay until you switch to the tab. **Show program status on tabs**, under
**Settings → Behavior**, is on by default.

See [program status](../guide/tabs-and-panes.md#program-status).

## Taskbar and Dock menus

Right-clicking Muxus in the Windows taskbar now offers **New window** and the hosts and
workspaces used most recently, which can be pinned to the list. The macOS Dock menu has the
same entries, and Linux launchers offer **New Window**. A recent host opens as a new tab in
the window used last, and a recent workspace in a window of its own. The new
`--new-window` flag opens another, empty window from the command line.

See [taskbar and Dock](../guide/the-window.md#taskbar-and-dock) and the
[command line](../reference/cli.md#desktop-launch-targets).

## Nix and NixOS

Muxus now ships a flake that builds the latest release from source:
`nix run github:FloSch62/muxus` tries it without installing, and NixOS configurations can use
its package or overlay. `nix develop` opens a shell with Node, pnpm and the native addon
toolchain for working on Muxus.

See [Nix and NixOS](../install/nix.md).

## Smaller improvements and fixes

- With the GPU renderer on, terminals opened at startup no longer draw text in a fallback
  font until the renderer is toggled; they measure their cells again once the terminal font
  has loaded, bold included.

This release also moves to Electron 45.2 and a newer xterm.js, and refreshes Fastify,
TanStack Query and development tools.
