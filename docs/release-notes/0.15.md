# Release 0.15

:material-calendar: 7 November 2026 · [Full changelog](https://github.com/FloSch62/muxus/compare/v0.14.0...v0.15.0)

Release 0.15 works with many hosts at once. A script runs on a whole folder or selection and
shows what each host printed, a host can be duplicated into a numbered series, and jump
routes and gateways can fall back to others when the first one is down. Web pages join the
host list, optionally through an SSH gateway, and hosts can connect with the system OpenSSH
client for Kerberos and anything else `ssh_config` sets.

## Scripts on many hosts

**Scripts** keeps scripts in Muxus and runs one on many SSH hosts. Open it from a host
(**Run script…**), a selection, a folder (**Run script on hosts in this folder…**,
subfolders included) or the quick launcher.

- **How they run.** **All at once**, **in batches of *n*** or **one by one**, optionally
  stopping at the first host that fails, with a time limit per host.
- **The script.** It is copied to the host and run with `sh`, or with the interpreter its
  `#!` line names, with an empty standard input so nothing waits for an answer.
- **Results.** Each host's state, exit code, duration and output, as it arrives. **Run again
  on failed hosts** repeats the run on just those.

Each host connects the way its terminal tab would, and password and host key questions from
several hosts appear one at a time.

See [scripts on many hosts](../guide/scripts.md).

## Web pages

A new **Web** host keeps a page's address in the host list, with the same folders, colours
and search, and opens it in its own Muxus browser window. Each page keeps its own cookies,
and a self-signed certificate can be accepted for that window only.

With **Connection route → SSH gateway**, Muxus connects to the gateway, starts a SOCKS5 proxy
on a free local port and points the page's window at it. Every request goes through the
gateway, name lookups included, so internal names and addresses only the gateway can reach
work, and HTTPS stays end to end. The proxy stops when the window closes.

See [web pages](../guide/web-pages.md).

## Fallback jump routes and gateways

Under an SSH host's jump chain, **Add fallback route** lists other jump routes to try, in
order. Muxus moves to the next one when a jump host cannot be reached, refuses the login or
cannot reach the target, and the status line says which route it is trying. A login the
target itself refuses is not retried. Hosts in `ssh_config` keep their `ProxyJump` line as
the first route, and Muxus stores the fallbacks.

RDP, VNC, gNMI and NETCONF hosts get **Add fallback gateway**, a list of more SSH gateways
tried in order.

See [connection route](../guide/adding-hosts.md#connection-route) and
[remote desktop](../guide/remote-desktop.md).

## System OpenSSH

**Use system OpenSSH**, in a host's **Advanced** section and in bulk edit, connects with this
computer's `ssh` instead of the built-in client. `ssh` reads its own config, including `Match`
blocks, so Kerberos (GSSAPI) works, and prompts and errors are its own. On Linux and macOS
the file browser, status bar statistics and container discovery share the terminal's login.
Muxus tunnels, scripts, fallback routes and the password vault are not available for these
hosts, and are greyed out where they are offered.

See [system OpenSSH](../reference/ssh-config.md#system-openssh).

## A series of hosts from one

In **Duplicate** and **Add host**, a number range in the alias, such as `web[2-10]`, creates
one host per number with the same settings. A leading zero keeps the width (`db[01-12]`), the
HostName follows along or takes a range of its own (`10.0.0.[12-20]`), and the line under the
alias shows what will be created before you save.

See [your hosts](../guide/hosts.md#host-rows).

## Smaller improvements and fixes

- New installs paint terminals with the GPU renderer. **Settings → Terminal → GPU renderer
  (WebGL)** still turns it off, and existing installs keep their setting.
- **Import** under **Settings → Appearance → Custom color schemes** takes several files at
  once. A file that can't be read doesn't stop the others, and schemes you already have are
  skipped. See [custom colour schemes](../guide/terminal.md#custom-colour-schemes).
- A host's containers, labs, clusters and VMs show as one small mark of logos in the sidebar,
  with the counts in its tooltip, so the host's name keeps its width.
- The dark terminal theme picker lists dark schemes before light ones.
- On macOS, the window controls stay centered in the smaller titlebar of focus mode.
- A port forward on a connection that died, for example after hibernating, no longer crashes
  the app with *Not connected*.
- Vertical box-drawing lines in the DOM renderer stay within their row again, as before 0.14.

This release also moves to Electron 45.2.3 and refreshes Fastify, TanStack Query, Vite and
development tools.

Thanks to [@kpatr1981](https://github.com/kpatr1981) for scripts on many hosts, web pages,
fallback routes and gateways, and numbered host series.
