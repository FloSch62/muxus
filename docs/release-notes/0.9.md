# Release 0.9

:material-calendar: 4 October 2026 · [Full changelog](https://github.com/FloSch62/muxus/compare/v0.8.1...v0.9.0)

Release 0.9 makes larger host lists easier to keep consistent: several hosts can now be
edited at once. Terminal sessions can be written to plain-text log files while they run,
terminal colour schemes can be your own, and other tools can open SSH sessions in Muxus
from the command line.

## Edit several hosts at once

Select hosts in the sidebar with ++ctrl++ + click (++cmd++ + click on macOS) and
++shift++ + click, or from the keyboard with ++shift+space++ and ++shift+up++ /
++shift+down++, then choose **Edit…**. A folder's menu offers **Edit *n* hosts…** for
everything inside it.

The bulk editor shows the settings the hosts share and reads **Multiple values** where they
differ. Only the settings you change are written: folder, colour, user, port, host
verification, agent and X11 forwarding, console compatibility, terminal colours,
highlighting profile and session logging. For hosts in `ssh_config`, only the lines of the
changed options are rewritten, so comments and every other option stay exactly as they
were.

See [editing several hosts at once](../guide/hosts.md#editing-several-hosts-at-once).

## Log files for terminal sessions

A terminal session can be written to a plain-text log file while it runs, independent of
session history. **Log session to file…** in the terminal-actions menu starts one for the
current session, and **Write log files** in a logging policy starts one for every new
session. The file holds the same text as the **Clean log** export and is complete when the
session ends.

See [log files](../guide/session-history.md#log-files).

## Your own terminal colour schemes

**Settings → Appearance → Custom color schemes** holds terminal colour schemes of your own.
Start one as a copy of any scheme, or import Windows Terminal and iTerm2 scheme files.
Custom schemes are listed first in the terminal theme pickers and in each host's terminal
appearance, and they are part of a backup.

See [custom colour schemes](../guide/terminal.md#custom-colour-schemes).

## Open SSH sessions from other tools

`muxus --connect [user@]host[:port]` opens an SSH tab to any host, including one that is
not in Muxus or `~/.ssh/config`, so a monitoring system or inventory with its own device
list can hand a device straight to Muxus. Matching `ssh_config` blocks still supply keys and
jump hosts, and passwords are asked for in the terminal as usual.

See [ad-hoc SSH connections](../reference/cli.md#ad-hoc-ssh-connections).

## Smaller improvements and fixes

- The **Terminal** entry at the start of a session's file strip, or ++ctrl+grave++, brings
  the terminal back in front of open files, which keep their unsaved changes. See
  [the file editor](../guide/editor.md).
- The desktop app connects to Windows RDP hosts that use the self-signed certificate
  Windows creates, instead of failing with "Muxus could not connect to the remote
  computer." See [Windows' own certificate](../reference/security.md#remote-desktops).
- Text fields show exactly what was typed: font ligatures no longer draw `<=`, `=>` or
  `->` as a single symbol, so regex highlighting rules read back correctly.
- Undoing an edit in **Settings → Session logging** clears its **Unsaved changes** marker,
  and closing Settings no longer asks to discard changes that were reverted.
