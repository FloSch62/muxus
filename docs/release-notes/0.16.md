# Release 0.16

:material-calendar: 22 November 2026 · [Full changelog](https://github.com/FloSch62/muxus/compare/v0.15.1...v0.16.0)

Release 0.16 gives the window a new shape and SSH a new engine. The sidebar becomes a rail
with one panel beside it, the panes are sheets on one canvas, a window's tabs can be tiled in
one click, and hosts get more layouts, a tab of their own and icons. A host monitor shows
every connected host at a glance, team host lists can be followed and shared, and logins can
take their password from an external password manager. Underneath, SSH now runs on a native engine written in Rust, and the file browser
resumes interrupted transfers and downloads whole folders.

## A new window

- **Sidebar rail.** A rail of icons runs along the window edge with one panel beside it:
  **Hosts**, **File browser**, **Containers & VMs** or **Port forwarding**. Containers and port
  forwarding are no longer panels of their own beside the panes. Hovering an icon shows its
  label, and **Pin labels** keeps them open. Host monitor, session history, appearance,
  keyboard shortcuts and settings moved from the top bar to the rail.
- **Sheets on one canvas.** Every pane is a rounded sheet like the sidebar's panel, with the
  tab strip at its top and a small gap around it. The gap between two panes is the handle that
  resizes them; a double-click evens them out. A terminal runs to the edge of its sheet.
- **A lighter dark theme.** The dark surfaces are lifted and further apart, edges are visible
  and secondary text is brighter. The terminal colour schemes are unchanged.
- **File browser in the sidebar.** The file browser is a sidebar panel only; the option to
  open it beside each terminal is gone. **Fill the window** spreads it over the panes without
  resizing the terminals behind it, and Esc shrinks it back.
- **Tile tabs.** **Arrange tabs**, after the split buttons of each tab strip, gives every tab
  of the window a pane of its own: **Tile tabs vertically** sets them side by side, **Tile
  tabs horizontally** stacks them, and with more tabs both wrap into a grid that keeps the tab
  numbers. Tiling stays on, so new sessions join the grid, until you split, resize or place a
  tab yourself; **Tabs** puts them back in one pane. A workspace saves it, and no session
  reconnects. The same commands are in the pane menu and the quick launcher.
- A click on a split divider no longer moves it; it only moves once the pointer does.

A sidebar that was hidden before the upgrade is shown once on the first start, because the
buttons that left the top bar are in it.

See [the window](../guide/the-window.md#sidebar) and [tiling
tabs](../guide/tabs-and-panes.md#moving-around).

## Hosts: layouts, a tab and icons

- **Layouts.** Beside the tree, the hosts panel has a flat **list**, grouped by last use, name
  or kind, and a **folder** view that shows one folder at a time with a breadcrumb.
- **Hosts tab.** **Open the hosts as a tab** shows every saved host in a pane, as cards or as a
  sortable table, one section per folder, with search and filters by kind. Hosts can be
  dragged between sections, onto sidebar folders and onto a tab strip to open a session there.
- **Host icons.** A host can be given an icon of its own: 36 general icons such as server,
  database, router or firewall, and 63 marks of operating systems, platforms, network vendors
  and clouds. **Icon** sits below the colour swatches in every host editor, the organize
  dialog and bulk edit, and the picker searches other names too (`k8s`, `rhel`, `nas`).
- The tree indents each level further, and hosts line up with the folders beside them.

See [other layouts](../guide/hosts.md#other-layouts), [the hosts
tab](../guide/hosts.md#the-hosts-tab) and [host icons](../guide/hosts.md#host-icons).

## Host monitor

A **host monitor** tab lists this computer and every connected host with latency, CPU, load,
memory, disk, disk I/O, network and uptime, plus swap, GPU, users, system and kernel under
**Columns**. Sort by any column, filter the list, and click a host to go to its tab. Hosts are
read over the connection that is already open, every 5 seconds by default, and only while the
tab is shown. Muxus dials nothing for it except the hosts on an opt-in **Keep connected**
list, and a connection that has not run a command, as on some network devices, is only read
after **Read anyway**.

See [host monitor](../guide/host-monitor.md).

## Listening ports

Every host in **Containers & VMs** ends in **Listening ports**: the TCP ports it listens on,
the program behind each and who can reach it. On an SSH host, **Forward to this computer**
forwards a port in one click, on the same port number when it is free, and the line then
opens `localhost:<port>` in the browser. A port that a container publishes is listed under the
container's name, and lab nodes show their published ports, so a Containerlab lab's Grafana or
Prometheus is one click away. Containerlab's own helper containers are no longer listed as
plain containers.

See [listening ports](../guide/environments.md#listening-ports).

## Shared session lists

Teams can follow one list of hosts, as with MobaXterm's shared sessions. **+ → Shared sessions
link…** reads a list from a web address or a file, network shares included: a MobaXterm
session file, a Muxus backup, or the list that **Share folder…** writes from any folder. The
hosts land in a folder of their own and are checked again at startup and every 15 minutes,
hour or day. A setting you changed locally is kept unless the list changes that same setting,
and a list cannot set `ProxyCommand`, agent forwarding, remote forwards or host key checking.
Passwords and private keys are never written to a shared list.

The sidebar's **+** is now a menu: **New host…**, **New folder…** and **Shared sessions
link…**.

See [shared sessions](../guide/hosts.md#shared-sessions).

## Passwords from a password manager

A host, an RDP or VNC host, or a folder can take its password from an entry in an external
password manager: KeePass and KeePassXC databases, pass and gopass, 1Password, Bitwarden and
Vaultwarden, Proton Pass, LastPass and Dashlane. Muxus stores which entry to use, never the
password, and reads it each time a login asks for one. Connect a manager under **Settings →
Passwords → Password managers** and pick an entry in the host editor. A locked KeePass
database or Bitwarden vault can be unlocked from the connection's own prompt.

See [passwords from a password manager](../guide/connecting.md#passwords-from-a-password-manager).

## A new SSH engine

SSH connections now run through a native engine written in Rust on russh. Encryption and the
bytes of terminals, file transfers, port forwards, agent forwarding and X11 move off the
app's main thread; host keys, the login order, prompts and `ssh_config` work as before.

A few things change with it:

- **Send BREAK** is no longer offered on SSH sessions. Serial and Telnet keep it.
- arcfour, blowfish-cbc, cast128-cbc, hmac-md5, the `-96` MACs and hmac-ripemd160 are no longer
  available. CBC, 3DES, SHA-1, group1/group14 and ssh-dss still work on request, so the
  **Legacy device algorithms** preset is unchanged. `mlkem768x25519-sha256` is new at the
  head of the defaults.
- DSA key files in the old PEM format are no longer read; OpenSSH-format DSA keys still are.
- A port forward whose local end takes nothing for 10 seconds is closed, so one stuck program
  can't slow the other sessions on the same connection.

Building Muxus from source now needs Rust. See [building from source](../install/from-source.md).

## File browser

- **Resume.** A download or an upload of 1 MiB or more that loses its connection continues
  where it stopped the next time the same file is transferred, if the file has not changed.
- **Folders.** Download takes folders, alone or with files, and recreates them in the local
  folder you pick. It says how many files and how much it will save before it starts.
- **Sorting and filtering.** Click **Name**, **Size** or **Modified** to sort, and again to
  reverse. **Filter by name** narrows the folder, and the eye button hides dotfiles.
- Uploaded files are no longer world-writable: a new file is created with `0644`, narrowed by
  the server's umask, as OpenSSH's `sftp` does.
- An upload that fails at the start shows its error at once instead of after a minute, and one
  whose connection drops fails instead of hanging, which also kept Muxus from quitting.
- *Cancelled* only shows after **Cancel**, not when the browser closes or the tab switches; a
  dropped connection says so.
- A file rewritten on the server under the same name downloads with its new content instead
  of a stale copy.
- On Windows, picking Downloads itself for a download of several files no longer leaves the
  folder picker stuck.

See [files](../guide/files.md#transferring).

## Smaller improvements and fixes

- A backup now holds workspaces, saved scripts, saved NETCONF and gNMI requests, connected
  password managers and the entry each host logs in with, plus sixteen settings it used to
  miss, among them keyboard shortcuts. A workspace open in a window is left as it is on
  restore. See [backup & data](../guide/settings.md#backup-data).
- Hosts that ask for the password first and only then offer a second factor, as many Duo
  setups do, can be reached with the built-in client. The saved password is reused, so only
  the code is asked on later logins, and Duo's menu of options shows in full.
- Resizing the window while a password or host key prompt is open no longer cancels the login,
  and cancelling a sign-in prompt no longer brings it back three times.
- Non-ASCII characters in imported MobaXterm folder and session names, such as `»` or `é`, come
  through instead of `�`. Folders imported before need to be imported again or renamed.
- The port forwarding panel lists a new forward or connection at once instead of several
  seconds later.
- With the GPU renderer, dark text on a light background is no longer thin, and switching the
  renderer no longer resizes the session.
- In the host editor, a key added under **Add key** clears the field, so it is not added twice.
- Switches under **Terminal appearance** in the host editor are no longer cut off.
- The documentation moved to [muxus.app](https://muxus.app/). Older builds still find updates
  through the previous address.

This release also moves to Electron 45.4.1, Node 24.22.3 and pnpm 12.21.0, and refreshes
xterm.js, TanStack Query, Vite, zustand, ws and development tools.
