# Release 0.10

:material-calendar: 8 October 2026 · [Full changelog](https://github.com/FloSch62/muxus/compare/v0.9.0...v0.10.0)

Release 0.10 shows more about the hosts you work on: a status bar with the active host's
statistics, a summary of what each SSH connection negotiated, and a diagnosis when one
fails. Remote files open in local programs and upload again when saved, the file browser
can live in the sidebar, tunnels can start with Muxus and reconnect on their own, and
command buttons can be sorted into groups per host.

## Host statistics in a status bar

A status bar along the bottom of the window describes the host of the active tab: host
name, operating system, CPU, memory, disk, network traffic, uptime and logged-in users,
with details in tooltips. The CPU, memory and disk meters turn amber at 80% and red at 95%.

SSH hosts are read over the connection that is already open with a short, read-only `sh`
script, so nothing is installed and no second login is needed. Linux hosts report every
item, and macOS and BSD hosts what their tools provide. Local terminals show the computer
they run on. Only the tab in front is read, and nothing is read while the window is hidden.

The bar is on by default. Right-click it, or use **Settings → Appearance → Status bar**, to
choose the items or hide it.

See [the status bar](../guide/the-window.md#status-bar).

## Diagnose a failed connection

When an SSH or Telnet session fails or drops, press ++d++ in its terminal instead of
reconnecting. Muxus checks DNS, ping, a TCP connection to each address and, for SSH, the
server's greeting, the SSH agent and the configured key files, then names the likely cause.
The checks need no extra tools or administrator rights, so they work the same on Windows,
macOS and Linux. Any other key still reconnects.

See [diagnosing a failed connection](../guide/connecting.md#diagnosing-a-failed-connection).

## A summary when an SSH session connects

**Show a summary when an SSH session connects** in **Settings → Behavior** starts each new
SSH session with what the connection negotiated: the route through any jump hosts, the
server software, the login method, the cipher and key exchange, and whether compression,
the SFTP browser, X11 forwarding and agent forwarding are active. A feature that is off says
why, for example when the server refused X11. The switch is off by default.

See [connection summary](../guide/connecting.md#connection-summary).

## Open remote files with local programs

The file browser's row menu has **Open with default program** and **Open with…** in the
desktop app, so an HTML page opens in the browser, an image in a viewer or a `.drawio`
diagram in draw.io without downloading it by hand first. On Linux, **Open with…** lists the
installed programs, with those that handle the file's type at the top.

When the program saves the file, Muxus asks **Upload changes to *file*?** and uploads it back
to the same path; a checkbox uploads later saves without asking. If the file on the server
changed in the meantime, Muxus asks before replacing it.

See [opening files with local programs](../guide/files.md#opening-files-with-local-programs).

## The file browser in the sidebar

The file browser can live in the sidebar instead of beside each terminal: one browser for
the window that follows the active SSH session. Vertical tabs along the window edge switch
the sidebar between **Hosts** and **File browser**, and transfers keep running while the
hosts are in front. **Move to the sidebar** in the browser's header, or **Settings →
Appearance → Layout**, moves it there.

See [docking it in the sidebar](../guide/files.md#docking-it-in-the-sidebar).

## Tunnels that start with Muxus and reconnect

Saved tunnels have two switches, both off by default. **Start when Muxus starts** brings a
tunnel up as Muxus opens, without a terminal. **Reconnect automatically** brings it back
after its SSH connection drops, retrying after 2, 5, 15 and 30 seconds and then once a
minute. These automatic starts never prompt: if a login needs a passphrase, a 2FA code or a
new host key, the tunnel shows **Sign-in needed** and starts with the usual prompts from its
play button.

See [starting with Muxus and reconnecting](../guide/tunnels.md#starting-with-muxus-and-reconnecting).

## Command button groups

Command buttons can be sorted into named groups, such as one per vendor, and the bar shows
one group at a time with a selector at its left end. Buttons can also carry a colour, and a
button can be duplicated as a starting point for a similar command.

A host can choose the group its sessions show: tick **Always show *group* for *host*** in the
bar's group menu, or set **Command button group** under **Terminal appearance** in the host
editor or the bulk editor. Existing buttons land in the **Default** group, so nothing
changes until a second group is created.

See [groups](../guide/commands.md#groups) and
[a group per host](../guide/commands.md#a-group-per-host).

## Selecting, moving and deleting hosts

- Selected hosts can be moved and deleted together: drag one of them, or use **Move *n*
  selected hosts…** and **Delete *n* selected hosts** in its right-click menu or the
  selection bar's buttons. Deleting asks once and names the hosts. See
  [editing several hosts at once](../guide/hosts.md#editing-several-hosts-at-once).
- ++shift++ + click now selects every host from the last one clicked, without connecting.
  Another session to a host that is already open is a middle-click away; ++shift+enter++
  and ++shift++ + double-click still open one too.
- **Open hosts with** in **Settings → Behavior** can be set to **Double-click**, so a single
  click selects hosts as in a file manager. See
  [opening with a double-click](../guide/hosts.md#opening-with-a-double-click).

## Smaller improvements and fixes

- **Settings → Behavior → Save new SSH hosts in** chooses whether the host editor starts new
  SSH hosts in OpenSSH config or in Muxus app data. See
  [adding & editing hosts](../guide/adding-hosts.md).
- **Remember passwords by default** in **Settings → Passwords** opens every password prompt
  with **Remember this password** already selected.
- Further connections behind a jump host, such as a duplicated tab to a device that allows
  one session per connection, go through the jump host's existing connection instead of
  logging in to it again. See [connecting](../guide/connecting.md).
- A reconnected SSH tab returns to its previous directory without typing a `cd` command
  into the shell, so nothing is echoed twice or added to the shell history.
- Remote desktops: ++shift++, ++ctrl++ and ++alt++ stay held on Windows hosts, AltGr works
  on Linux, horizontal scrolling goes the right way, and a drag released outside the
  desktop lets go of the mouse button. Pasting more than 16 MiB no longer closes the
  session, and a remote desktop closed while it connects no longer dials the host directly
  instead of through its SSH gateway. See [remote desktop](../guide/remote-desktop.md).
- Replacing an existing file works on SFTP servers without OpenSSH's `posix-rename`
  extension.
- Stopping a remote forward whose connection had already closed no longer shows an error.

This release also refreshes Electron, terminal packages and development tools.
